The phone-to-laptop sequence is an acceptance shot to capture against a running development backend; automated tests cover session-scoped event delivery, but a physical two-device recording has not been verified in this checkout. Do not present a mock/local preview as live WebSocket sync. ## Recording checklist

- Run the acceptance sequence from [PHONE_DEMO_GUIDE.md](PHONE_DEMO_GUIDE.md); confirm backend and both clients use the same account.
- Confirm the phone is using Flutter Web for Needle voice capture. The Android app shell currently supports typed/manual capture and local alerts, not native Needle voice inference.
- Confirm Redact model initialization and send a synthetic PII test before filming. Never substitute a fabricated network panel or claim the blocked save succeeded.
- Use the benchmark reminder only after verifying it produces an actionable call on the recording setup. The six-utterance benchmark shows five of six examples suppressed or misrouted; do not imply general intent accuracy.
- Capture the two-client create/update/delete sequence with actual clients and no refresh. If that live acceptance shot cannot be produced before submission, replace that segment with an explicitly labeled test/architecture view and disclose that the physical demo remains unverified.
- Keep the finished cut at or under 2:00; captions should preserve the privacy and verification caveats if voiceover is trimmed.
