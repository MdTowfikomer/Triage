# Contributing

Thanks for helping improve Triage. By opening a pull request, you agree that
your contribution may be distributed under the project license.

## Before submitting

- Open an issue for a large feature or behavior change so its scope can be
  discussed.
- Keep changes focused and include tests for behavior that can be tested.
- Run the relevant Flutter tests and analysis from `triage/triage_flutter`;
  run Serverpod tests for backend changes.
- Do not commit API keys, signing files, personal contact data, audio, model
  weights, generated build output, or production logs.
- Use fake values in fixtures and screenshots. Do not include real user data.

## Pull requests

Describe the user-visible change, verification performed, and any platform or
backend setup still required. Keep generated Serverpod files consistent with
their source definitions and use the repository's documented generation flow.

By submitting a contribution, you certify that you have the right to submit it
under the project license. A DCO sign-off is welcome but is not currently
required.
